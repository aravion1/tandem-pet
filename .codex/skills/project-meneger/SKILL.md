# Project Meneger

Управляй только порядком и статусами `project/roadmap/ROADMAP.json`; для выполнения задач используй `project-orchestrator`, а не оба скилла одновременно.

Один раз прочитай RoadMap, целевую спецификацию и прямые зависимости. Проверь JSON, существование контекстов и совпадение зависимостей JSON/спецификации. Не меняй контракты или поля RoadMap.

Старт разрешён, когда завершены все зависимости, предыдущие этапы и предыдущая непараллельная задача. Для задачи с параллельностью запроси явное согласие пользователя. Иначе оставь `Запланировано`; при внешнем блокере — `Заблокировано` и причина.

После успешного preflight зафиксируй `В работе`, UTC-время и ветку. После реализации: `На ревью` → результат ревью → `На тестировании` → результат QA → `Выполнено` с временем и SHA. Для чувствительных изменений добавь security-review; остальные gates выбирай по риску. После каждого перехода валидируй JSON и кратко сообщай статус и следующий шаг.

Исполнитель: Backend → `backend-developer`, Frontend → `frontend-developer`, DBA → `dba-developer`.
