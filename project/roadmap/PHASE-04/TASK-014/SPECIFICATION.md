# ID задачи: TASK-014

## Название задачи

Событийные уведомления и заменяемые каналы доставки.

## Исполнитель

Backend

## Полное описание

Реализовать очередь уведомлений, реестр каналов и адаптерные интерфейсы для SMS, Telegram, MAX и push. Подключение конкретных поставщиков не входит в задачу; интерфейсы должны позволять подключить их без изменения доменной логики.

## Контракты данных

`Notification {id,user_id,event_type,payload,created_at,delivered_at}` из TASK-005. Контракт адаптера: `send(recipient, message, payload): DeliveryResult`; каналы `sms|telegram|max|push`. `event_type`: `work_status_changed`, `work_comment_created`, `task_assigned`, `news_published`, `infoboard_published`, `discussion_invited`.

## Эндпоинты

Публичные HTTP-эндпоинты не добавляются. Используются доменные события после операций TASK-006, TASK-008 и TASK-010; обработка выполняется очередью Redis.

## Бизнес-логика

При каждом утверждённом событии определить адресатов и поставить доставку во все доступные им каналы. Для активации и восстановления в TASK-002 используется только SMS-адаптер. Ошибка одного канала не отменяет попытки остальных; результат доставки и ошибка фиксируются в журнале без секретов.

## Зависимости

TASK-002: SMS для аутентификации; TASK-004: Redis/очередь/секреты; TASK-005: уведомления; TASK-006, TASK-008, TASK-010: источники событий.

## Критерии готовности

Тесты подтверждают создание уведомления для каждого из шести событий, постановку всех доступных каналов, изоляцию сбоя канала и использование SMS в сценариях аутентификации.
